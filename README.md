# blue-matching

## 求人アピールタグ

求人タグは一覧の絞り込みや求人カード・詳細表示に使います。日払いと給与手渡し、未経験歓迎と即日勤務、夜勤と給与条件は別々に選択できます。「高収入」のような基準が曖昧なタグは避け、給与欄に金額を記載してください。タグは実際に提供できる条件だけを選択してください。既存求人の旧複合タグは表示・検索・編集時に新しいタグへ読み替えます。

求人では給与区分と下限・上限、締日・支給日などを登録できます。資格は必須・歓迎を分け、実務経験も「指定なし」「経験者歓迎（未経験可）」「必須」から明記できます。これらの項目を保存するには、`supabase/migrations/20261031_add_job_pay_and_qualification_details.sql` をSupabase SQL Editorで実行してください。

求人・求職者の勤務地は地方別に都道府県を複数選び、選んだ都道府県ごとに市区町村を任意入力できます。既存の勤務地も引き続き表示・編集できます。求人・希望勤務地の保存にはそれぞれ500文字まで使えます。求職者の希望勤務地を500文字に拡張するには `supabase/migrations/20261031_expand_seeker_location_length.sql` をSupabase SQL Editorで実行してください。

求人では電話番号・LINE IDを収集せず、応募者とはサイト内の「応募・メッセージ」で連絡します。既存求人に保存済みの連絡先は削除せず、公開APIから読めないようにするには `supabase/migrations/20261031_secure_job_contact_details.sql` を実行してください。

## 退会（アカウント削除）

マイページ下部の「退会する」から、本人が退会できます。事前に `supabase/migrations/20261102_add_account_deletion.sql` をSupabase SQL Editorで実行してください。退会すると、プロフィール・お気に入り・通知・掲載中の求人が削除されます。応募とメッセージは相手側の履歴が壊れないよう、氏名や本文を消して「退会したユーザー」として残り、応募は終了扱いになります。

## アカウント停止と投稿数の制限

運営管理画面の通報カードから、投稿者のアカウントを停止・解除できます。停止すると、そのユーザーの求人はすべて非表示になり、求人の投稿・応募・メッセージ送信ができなくなります。解除すると、停止が理由で非表示にした求人だけ元に戻ります。運営者のアカウントは停止できません。`supabase/migrations/20261103_add_user_suspension_and_post_limits.sql` を実行してください。

また、一般ユーザーの投稿は、掲載中20件まで・24時間で新規10件までに制限されます（運営者とSQL Editorは対象外）。

## 求人の共有と複製

求人の詳細に「LINEで送る」と「リンクをコピー」があり、共有リンク（`/?job=求人ID`）を開くと、その求人の詳細が直接開きます。掲載終了・非公開の求人は開けません。企業マイページの求人には「複製」ボタンがあり、内容をコピーした新規投稿フォームを開けます（掲載期間は新しく選びます）。

## 検索条件の保存と新着の知らせ

ログイン中は、絞り込み条件を「この条件を保存」で5件まで保存できます。保存した条件は一覧の上に表示され、前回その条件を開いた後に掲載された求人があると「新着N件」と出ます。条件を押すと、その条件で絞り込み、新着の確認日時を更新します。事前に `supabase/migrations/20261104_add_saved_searches.sql` を実行してください。新着のメール通知は、メール設定（Resend独自ドメイン）と一緒に仕上げで対応します。

## 求人の編集・募集状態

新規登録はログイン画面とは別の「新規登録」ページで行い、求職者または企業・親方のアカウント種類を登録時に選びます。ログイン画面ではメールアドレスとパスワードを入力し、アカウント種類は選びません。種類はデータベースに保存されるため、次回以降のログインでは選択不要です。種類が未保存の既存アカウントのみ、最初のログイン時に一度選択します。既存求人を管理する場合は企業・親方を選んでください。種類はデータベース上で固定され、変更できません。ログイン後は選択した種類の画面だけが表示され、求職者向け・企業向け画面を切り替えられません。未ログイン時は求人一覧だけが表示され、ヘッダーの「ログイン」からログイン画面を開けます。新規登録ページへはログイン画面内のリンクから移動できます。企業アカウントは自己申告区分で、事業者の本人確認は行っていません。求職者プロフィールの企業向け公開は初期状態でオフであり、本人が明示的に選んで保存した場合だけ公開されます。公開プロフィールは個人情報を含まない別テーブルに分離し、企業向け画面では公開に同意したプロフィールだけを検索できます。氏名・電話番号・メールアドレスは検索結果に含まれません。公開する情報に個人を特定できる内容を含めないでください。

求人情報はログイン不要で閲覧できます。お気に入り保存、サイト内応募、プロフィール保存などアカウントに紐づく操作にはログインが必要です。応募は求人詳細から専用の応募画面に進んで送信します。求人詳細からLINE・電話・SMSで直接連絡する機能はありません。

ログインすると、ヘッダーの「マイページ」からアカウント情報・ログアウト・各種管理画面を確認できます。マイページはオーバーレイで開き、閉じるボタン・背景クリック・Escキーで閉じると元の画面に戻ります。求職者はプロフィール・お気に入り・応募履歴・連絡と通知を確認できます。企業は求人を管理し、求人一覧エリアの「求職者検索」から、企業へのプロフィール公開を許可した求職者を希望職種・地域・資格・経験・給与条件で検索できます。検索結果には公開用プロフィールに保存した希望職種・勤務地・給与・資格・経験・体力自信度だけを表示し、氏名・電話番号・メールアドレスは表示しません。企業は「応募・メッセージ」から通知で応募者名・求人名を確認できます。通知を開くと応募内容と会話が別のオーバーレイで表示され、現在のタブやスクロール位置を保ったまま応募状況の更新やメッセージの送信ができます。通知一覧は未読を新しい順に先に表示し、既読はその下に新しい順で表示します。「通知未読／通知既読」は通知を確認したかどうかを示し、応募の「確認済み」とは別の状態です。企業と求職者は応募ごとの参加者だけが閲覧できるサイト内メッセージで連絡でき、電話番号・メールアドレスは応募先へ共有されません。未読通知にはメッセージ本文を含めず、相手にサイト内で知らせます。応募の閲覧・メッセージ送信は応募者本人または該当求人の投稿者に限られ、対応不要の応募には新しいメッセージを送信できません。求職者が企業の確認前に応募を取り消すと、応募データ・会話・関連通知を削除します。同じ求人へ再応募できます。求職者マイページではプロフィール・お気に入り・応募履歴・連絡と通知を切り替えて表示し、掲載求人の管理機能は表示しません。求人カードまたは詳細画面の☆ボタンでお気に入りに登録でき、一覧をお気に入りだけに絞り込めます。求職者プロフィールに希望職種を登録すると、求人の職種名・仕事内容へのキーワード一致をおすすめ順に反映します。希望勤務地は入力地域の一致、次に都道府県の一致を優先し、距離計算は行いません。希望給与区分・最低額は求人検索条件に反映され、おすすめ順にも反映されます。求人一覧は募集中のみの表示、勤務地・募集人数・給与区分・最低給与額での絞り込み、おすすめ順・新着順・給与額順・募集人数が少ない順の並び替えに対応します。求人登録では給与表記に加え、絞り込み用の給与区分と金額を任意で登録できます。タグは複数選択でき、選択したタグのいずれかを含む求人に絞り込みます。募集終了の求人では応募ボタンを表示しません。

現在の求職者マイページでは、企業からの連絡本文・返信／見送り操作と各種通知を「連絡・通知」画面にまとめています。未返信の連絡または未読通知がある場合、ログイン後に案内を表示し、ボタンから同画面を直接開けます。

求職者のおすすめ順では、求人カードにプロフィール希望職種・勤務地・給与区分・最低希望額のうち一致した項目と参考スコアを表示します。企業の求職者検索でも選択した自社求人に対して同じ条件の一致理由と参考スコアを確認できます。応募詳細の「応募者プロフィールを見る」から、本人が企業向け公開に同意している場合は匿名プロフィールを確認でき、公開していない場合はその案内が表示されます。プロフィールに氏名・連絡先は含めず、応募内容に戻って応募時の情報を確認できます。

求人詳細の「応募画面に進む」からサイト内の専用ページで応募できます。応募者の名前・プロフィールに登録済みの経験と資格・任意メッセージが該当求人の投稿者に共有され、電話番号は応募に含まれません。応募後は画面で次の手順を案内し、応募履歴はマイページに記録されます。新しい応募は企業へのサイト内通知と登録メールで知らせます。企業が応募を「確認済み」にすると応募者の履歴に反映され、応募者にも登録メールで通知します。応募状況と企業からの連絡は求職者マイページで確認できます。電話番号のSMS確認と、企業からの電話番号共有依頼・応募者の同意による共有は保留中です。

企業マイページでは、通知を開くと該当する応募者の名前・経験・資格・任意メッセージ・応募日時と会話を確認できます。企業が「確認済み」にした後から双方がメッセージを送信できます。今回は対応しない場合は「対応不要」を選び、必須の理由を入力します。理由は求職者の応募履歴にも表示されます。「確認済み」への更新時は応募者へ登録メールを送ります。応募には電話番号も含まれず、メッセージを含む応募情報は応募者と該当求人の投稿者だけが閲覧できます。対応不要の応募は履歴を閲覧できますが、新しいメッセージは送れません。ブロックリストは求職者プロフィール内に折りたたんで表示し、必要なら解除できます。

求人一覧では、求人ごとの囲み枠を使わず、余白・薄い区切り線・ホバー時の背景色で情報を見分けやすくします。募集状況・人数・職種・勤務地・給与を見比べやすく表示し、詳細条件は折りたたんでおき、必要なときだけ開けます。検索結果がない場合は理由と条件リセットを表示し、求人詳細では仕事内容・勤務地・給与を確認してから専用応募画面に進めます。スマートフォンでも操作しやすいボタンサイズと文字間隔にしています。未ログイン時は求人一覧だけが表示されます。

求人検索には「未経験歓迎」「寮・社宅あり」「資格取得支援」のクイック条件があります。求人には掲載・更新日時を表示しますが、企業の本人確認は行っていないため、確認済みバッジは表示せず、応募前に求人内容・条件を確認するよう案内しています。求職者・企業それぞれのマイページには、最初の操作を案内する使い方ガイドがあります。

マイページのテーブルを作成するには、Supabase SQL Editorで `supabase/migrations/20261026_add_user_dashboard.sql` を一度実行してください。先に `20261026_add_job_status.sql` と `20261026_secure_job_ownership.sql` を実行し、求人の `is_closed`・`owner_id` とRLSを設定する必要があります。このマイページ移行はプロフィール・お気に入り・応募履歴のテーブルを追加し、RLSにより利用者本人または該当求人の投稿者だけにアクセスを許可します。アカウント区分と匿名プロフィール機能を有効にするには、その後 `supabase/migrations/20261026_add_account_types_and_public_seekers.sql` を実行してください。企業からの連絡リクエストを有効にするには、続けて `supabase/migrations/20261026_add_seeker_contact_requests.sql` を実行してください。サイト内通知を保存するには、続けて `supabase/migrations/20261027_add_notifications.sql` をSupabase SQL Editorで実行してください。アカウント区分の選択後、既存アカウントの種類を後から変更する機能はありません。
企業の求職者検索と公開同意のデータベース保護を有効にするには、アカウント種別・公開プロフィール移行の後に [`supabase/migrations/20261030_secure_public_seeker_search.sql`](./supabase/migrations/20261030_secure_public_seeker_search.sql) をSupabase SQL Editorで実行してください。このSQLは再実行可能で、以前の広い読み取りポリシーも削除します。非公開プロフィールの検索・読み取りを拒否し、本人が公開を許可したプロフィール項目だけを企業に表示します。企業は募集中の自社求人を選ぶと、希望職種・勤務地・給与区分・最低給与額・働き方の一致度を最大14点の参考スコアで確認し、点数順に求職者を並べ替えられます。経験・資格は候補者情報として表示しますが、マッチ順位の判定には使いません。求職者側もプロフィールの希望職種・勤務地・給与・働き方をおすすめ順に反映します。いずれのマッチ度も条件一致の目安であり、採用可能性を判定するものではありません。

拡充した職種・資格・働き方の選択肢と、求職者の働き方希望を有効にするには、`supabase/migrations/20261031_expand_work_preferences.sql` をSupabase SQL Editorで実行してください。求人と公開・非公開プロフィールの希望条件を保存する列を追加し、従来の働き方・体力自信度を新しい選択肢に移行します。公開プロフィールの既存の同意・読み取り制御は変更しません。
求人の始業・終業時間、休憩、残業目安、手当・待遇の詳細と、求職者の経験した作業を保存するには、上記の後に `supabase/migrations/20261031_add_job_conditions_and_experience.sql` をSupabase SQL Editorで実行してください。経験した作業の詳細は、求職者が匿名プロフィールの公開に同意した場合だけ企業に表示されます。求人の勤務条件は求人詳細に表示されます。
マイページのテーブルを作成するには、Supabase SQL Editorで `supabase/migrations/20261026_add_user_dashboard.sql` を一度実行してください。先に `20261026_add_job_status.sql` と `20261026_secure_job_ownership.sql` を実行し、求人の `is_closed`・`owner_id` とRLSを設定する必要があります。このマイページ移行はプロフィール・お気に入り・応募履歴のテーブルを追加し、RLSにより利用者本人または該当求人の投稿者だけにアクセスを許可します。アカウント区分と匿名プロフィール機能を有効にするには、その後 `supabase/migrations/20261026_add_account_types_and_public_seekers.sql` を実行してください。企業からの連絡リクエストを有効にするには、続けて `supabase/migrations/20261026_add_seeker_contact_requests.sql` を実行してください。サイト内通知を保存するには、続けて `supabase/migrations/20261027_add_notifications.sql` をSupabase SQL Editorで実行してください。アカウント区分の選択後、既存アカウントの種類を後から変更する機能はありません。

応募で電話番号を収集・共有しない運用に切り替えるには、上記の応募テーブル作成後に `supabase/migrations/20261030_remove_application_phone.sql` をSupabase SQL Editorで実行してください。この移行は応募テーブルに保存済みの応募者電話番号をすべて削除し、元に戻せません。プロフィールに登録された電話番号はこの移行の対象外で、応募先には共有されません。移行を実行してから新しい応募画面を公開してください。


求人の更新日時を表示するには、既存の求人・通知用SQL移行の後に `supabase/migrations/20261027_add_job_updated_at.sql` をSupabase SQL Editorで実行してください。求人を編集・募集終了にすると更新日時が記録されます。

登録メール通知を有効にするには、Resendで送信元ドメインを検証し、Supabase DashboardのEdge Function Secretsに `RESEND_API_KEY`、`RESEND_FROM_EMAIL`、`APP_URL` を登録してください。独自ドメインを使う場合は、そのオリジンを `APP_ORIGIN` にも設定します。その後、Supabase CLIで `supabase functions deploy send-notification --project-ref qefqlbkqewvahtqzqmfp` を実行してください。APIキーはHTMLやGitHubへ登録しないでください。通知メールは新しい応募・連絡リクエスト・求職者からの返信または見送りを知らせるだけで、応募内容・氏名・電話番号・メッセージ本文は含めません。メール設定が完了するまでは、操作は保存されますがメール通知は送信できず、画面に案内が表示されます。サイト内通知はデータベース移行後に利用できます。

## 事業者アカウントと求人の権限

求人の投稿・編集・募集終了・削除には事業者アカウントへのログインが必要です。サイトからメールアドレスとパスワードで新規登録できます。アカウント作成後に確認メールが届いた場合は、メール内のリンクを開いてからログインしてください。求職者の求人閲覧はログイン不要です。

求職者マイページのプロフィール・お気に入り・応募履歴・連絡と通知は、メニューを開かずに上部の横並びボタンで切り替えます。企業からの連絡本文と返信・見送り操作は通知一覧にまとめています。求職者向けには掲載求人管理を表示しません。表示領域の高さを固定して画面上部が切り替え時にずれないようにし、閉じるボタンは右上に配置しています。ログイン画面も暗転オーバーレイで開き、求人詳細など他の画面より手前に表示されます。

求人検索条件は求人カード一覧と背景色・枠線・余白で分けて表示します。企業マイページでは求人を管理し、「応募・メッセージ」から応募内容・通知・応募者とのメッセージを確認します。

ログイン画面の「パスワードを忘れた場合」から再設定メールを送信できます。再設定リンクは同じサイトへ戻るため、Supabase Dashboard の **Authentication → URL Configuration → Redirect URLs** に `https://blue-matching-pi.vercel.app/**` を登録してください。メール内のリンクをスマートフォンで開き、新しいパスワードを2回入力して保存します。

他の求人スキーマ移行（募集状態・勤務地・給与条件）をまだ実行していない場合は、先に「Supabase の準備」のSQLを実行し、その後に次のファイルを実行してください。この移行は `published_jobs` の既存RLSポリシーをすべて置き換え、公開読み取りと、投稿者本人に限定した作成・更新・削除を設定します。既存求人の `owner_id` は空のまま公開閲覧でき、投稿者に紐付けられないため管理操作はできません。既存求人のデータは削除されません。

### 新規登録のCAPTCHA（Cloudflare Turnstile）

1. CloudflareでTurnstileウィジェットを作成し、ドメインに `blue-matching-pi.vercel.app` を登録します。
2. 発行されたSitekeyを `index.html` の `cloudflare-turnstile-sitekey` メタタグの `content` に設定してサイトを再デプロイします。Sitekeyは公開用ですが、Secret keyはソースコードやGitHubに置かないでください。
3. Supabase Dashboardの **Authentication → Bot and Abuse Protection** でCAPTCHAを有効にし、Cloudflare Turnstileを選択してSecret keyを登録・保存します。サイト側のデプロイが完了する前にSupabase側を有効化すると、新規登録できなくなるため順番を守ってください。
4. 公開サイトでTurnstileが表示されることを確認し、CAPTCHAを完了してから新規登録できることをテストします。Turnstile確認に成功して新規登録を送信すると、Supabase AuthがSecret keyを使ってCloudflare Siteverifyをサーバー側で呼び出します。アプリのブラウザーコードからSiteverifyを直接呼び出したり、Secret keyを配置したりしないでください。

### 通知について

メール通知はResendの独自ドメイン設定が済むまで届かない場合があります。サイト内では、ヘッダーの「マイページ（未読N）」、ブラウザータブの件数、ログイン後の案内バナーで未読の通知・連絡・掲載期限の近い求人を知らせます。

### 確認メールをResendから送る（標準メール上限の回避）

Supabase標準メール送信はテスト向けで送信数が非常に限られます。Resendを使うには、送信元として使える独自ドメインを用意し、Resendにドメインを追加してDNSのSPF/DKIMレコードを設定・検証します。Vercelの `vercel.app` ドメインは送信者ドメインとして使えません。

1. ResendでAPI keyを作成し、ドメインをVerifiedにします。API keyはSupabase SMTPのパスワードとしてだけ設定し、共有しないでください。
2. Supabase Dashboardの **Authentication → Email → SMTP Settings** を開いて、Custom SMTPを有効にします。
3. 次を入力して保存します。
   - Host: `smtp.resend.com`
   - Port: `465`
   - Username: `resend`
   - Password: ResendのAPI key
   - Sender email: Resendで検証したドメイン上のアドレス（例: `auth@あなたのドメイン`）
   - Sender name: `blue-matching`
4. テスト登録または確認メール送信を一度だけ行い、受信できることを確認します。送信上限はResendの契約・アカウント状態にも従います。
